## The one open item, and why it is closed rather than pending

"Determine what ads should play based on what tags" reads two ways: tags scope
the slot, or tags match the page. **Both are already reachable through hooks
that ship today.**

```php
// Reading A - a slot only draws from its tag.
add_filter( 'wbam_ads_for_placement', function ( $ads, $placement_id ) {
    // includes/Modules/Placements/class-placement-engine.php:401
    // $ads is the already-gated list; drop what the slot should not show.
}, 10, 2 );

// Reading B - an ad follows matching content.
add_filter( 'wbam_should_display_ad', function ( $show, $ad_id ) {
    // includes/Modules/Targeting/class-targeting-engine.php:70
    return $show && /* ad's tags match this page */ true;
}, 10, 2 );
```

**Decision: build no feature for this yet.** A UI would mean picking a default
between two behaviours real site owners could want oppositely, plus a settings
surface, plus deciding what untagged ads do on upgrade, plus stating precedence
against the 3.0.0 site and advertiser gates. That is a lot of permanent surface
bought with one ambiguous sentence from one client. Nobody is blocked meanwhile
- the hooks answer both readings in a few lines.

Promote it into the plugin only when several sites ask for the *same* reading.
By then we would know which one to build.

`test_tagging_an_ad_does_not_change_delivery()` holds that line: tags are
organisation only, and the test fails loudly if delivery starts reading them by
accident.

## Known limits, stated rather than discovered

- **Select-all is one page.** All Ads paginates at 20, so "bulk action by tag"
  on 100 ads is five rounds, or raise per-page via Screen Options. Core behaves
  the same on every post list - not a defect, but it is less than "mass action
  by tag" sounds like.
- **Client has not confirmed tags over folders.** They asked for both folder
  organisation (#12) and multiple tags per ad (#10), which contradict. We built
  tags. The email explaining why is drafted at
  `~/Documents/work-artifacts/scratch/btc-ads-tags-client-email.md` and is
  **unsent**. The whole phase rests on that assumption.
