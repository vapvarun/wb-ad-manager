## What this plan scopes

Just the FREE-side deliverables. Pro management UX, advertiser portal, billing — those live in the PRO plan.

> **⚠️ ARCHITECTURAL PRINCIPLE:** wb-ads is the **ad engine**. We do NOT build video player infrastructure. Player owners (mediashield first, future plugins later) consume our REST contract to render ads inside their players. **Zero JS shipped from FREE wb-ads for in-video.**

### IN scope (FREE 2.12.0)

| Component | Detail |
|---|---|
| **Video ad type expansion** | Existing `video` ad type gets full IAB-compliant metadata: `_wbam_video_url`, `_wbam_video_vast_tag_url`, `_wbam_video_dimensions` (W×H), `_wbam_video_duration`, `_wbam_video_click_through_url`, `_wbam_video_format` (linear/non_linear), `_wbam_video_skip_after` (default value — players override per slot) |
| **New audio ad type** | Discriminator `_wbam_ad_kind = audio` on `wbam-ad`. Fields: `_wbam_audio_url`, `_wbam_audio_vast_tag_url`, `_wbam_audio_duration`, `_wbam_audio_click_through_url` |
| **VAST 4.x parser** | New `Frontend\Creative\VAST_Parser` (PHP, server-side only). Resolves wrapper chains up to 5 levels per IAB spec. Returns: media_file_url, mime, dimensions, click_through, tracking_events, skip_offset |
| **Creative resolver** | New `Frontend\Creative\Resolver`. Given a context (zone OR ad_id), returns a render-ready creative payload: URL, dimensions, duration, click_through, format, skip_after_default, tracking_pixels |
| **Event tracker** | New `Frontend\Creative\Tracker`. Records impression/q25/q50/q75/complete/skip/click. Persists to existing `wbam_pro_analytics` aggregator. Fires `wb_ads_event_recorded` action for cross-plugin mirroring |
| **REST: `GET /wb-ads/v1/creative`** | Public read. Query: `context` (zone:slug or ad:id), `format`, `position_hint`, `session_id`. Returns: full creative payload + tracking pixels. Rate-limited per IP |
| **REST: `POST /wb-ads/v1/event`** | Body: `ad_id`, `event_type`, `context`, `session_id`, `position_hint`, `client_timestamp`, `extra`. Permission: nonce for logged-in, rate-limited for anon. Side effects: persist event + fire `wb_ads_event_recorded` action + (if event=complete and pricing=CPM-V/A) signal Pro to debit wallet |
| **Filter surface** | `wb_ads_creative_resolved` (mutate response before return), `wb_ads_frequency_cap_types` (extend cap registry — Pro adds `per_session`) |

## Architecture (FREE-side)

```
HTTP request (from mediashield JS, or any other player consumer)
    │
    ▼
GET /wb-ads/v1/creative?context=zone:premium-pre-roll&format=linear&...
    │
    ▼
Frontend\Creative\Resolver
    ├─ resolves zone slug → ad_id via existing rotation engine
    ├─ if VAST tag URL: Frontend\Creative\VAST_Parser → resolved media_file_url
    ├─ apply_filters('wb_ads_creative_resolved', $payload, $context)
    └─ return JSON payload

POST /wb-ads/v1/event { ad_id, event_type=complete, session_id, ... }
    │
    ▼
Frontend\Creative\Tracker
    ├─ persist event to wbam_pro_analytics (existing pipeline)
    ├─ do_action('wb_ads_event_recorded', $event_type, $ad_id, $context)
    │   └─ mediashield-pro listens, mirrors to ms_playback_events
    └─ return 204 No Content
```

The two REST endpoints + two hooks are the entire FREE-side surface for in-video ads.
