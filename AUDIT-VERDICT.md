# Audit Verdict: wb-ad-manager (wb-ads-rotator-with-split-test)

**Branch audited:** `2.9.1` (checked out clean, HEAD `17da865` "Fix partnership form staying light in BuddyX/Reign dark mode"). Header/readme/package.json still say `2.9.0` — version bump has not happened yet on this branch.
**Pro pair audited (read-only, for hook-boundary contract checks only):** `/Users/varundubey/Documents/GitHub/wb-ad-manager-pro`, branch `1.7.2` (header/readme say `1.7.1`).
**Method:** static only — no browser, no code changes, no commits. Contract audit (`wp-contract-audit`), WPCS, a11y grep+static, manual security/perf/i18n/packaging review, and a real (non-committed, cleaned-up) `bin/build-zips.sh` packaging run.

## Shippable? WITH FIXES
The Free plugin (`wb-ad-manager`) is architecturally solid (clean autoloader, paginated admin lists, healthy REST permission model, working uninstall, packaging guard rails already in place) but ships with one confirmed, severe functional break: **ad click tracking never fires**, which silently guts the plugin's flagship "A/B Comparison — winner badge" feature. That must be fixed before release; it is a small, contained fix (class-name alignment), not a redesign.

## Sellable? WITH POLISH (Free), NOT YET (Pro combo)
Once the click-tracking break and the two a11y gaps (missing form labels, missing focus-visible) are fixed, the Free plugin is sellable-grade. The **Pro** side has two additional confirmed dead-feature bugs (advertiser/campaign lifecycle emails never fire; an orphaned Chart.js analytics dashboard shipped to every Pro admin page) that must be fixed before the combo zip goes out — a paying Pro customer would notice both (no approval/rejection/budget emails, and a broken "Ad Filter" on the analytics page).
